# A1.5 design — Green–Kubo cross-check of the Onsager coefficients

- **State:** draft for the author's approval; nothing is implemented. Issue:
  mines-of-morja/ucmd-analysis#2. Code review branch: `a1`.
- **Scope:** L₊₊, L₋₋, L₊₋ (and hence κ, t₊^COM) from velocity correlations, compared with the Einstein form
  in `transport()`. Not in scope: viscosity (exists, `viscosity.py`), other frames (see A1.5.md).
- **Open:** the three questions of the issue are answered in §2–§4; decisions for the author in §7.
  Items marked "mine" are my own derivations or estimates, not printed equations.

## 1. Relation of the two forms

With J_i(t) = Σ_a v_a the summed centre-of-mass velocity of the molecules of ionic species i in the
barycentric frame, the code's Einstein form is L_ij = 1/(6 k_B T V) · d/dt ⟨ΔR_i · ΔR_j⟩ (docstring of
`transport.py`, after Fong et al. 2020; Lehnert 2025 Eq. 3). Since d/dt ⟨ΔR_i·ΔR_j⟩ = 2 ∫₀ᵗ ⟨J_i(0)·J_j(t′)⟩ dt′
(mine, standard Helfand relation), the Green–Kubo form is

> L_ij = 1/(3 k_B T V) · ∫₀^∞ ⟨J_i(0) · J_j(t)⟩ dt          (1, mine)

with the same normalisation, so both forms give identical numbers for the same trajectory in the limit of
continuous sampling. **Consequence:** the two are not independent estimates. The cross-check tests the
implementation, the sampling interval and the regime selection, not the statistical error.

## 2. Do our trajectories carry velocities, and at what interval?

- **Spec:** `particles/all/velocity` is **optional**, unit nm ps⁻¹ (`spec/trajectory-h5md.md`, line 21). Run
  config `[output.trajectory] velocities` defaults to **false** (`crates/ucmd-io/src/config.rs`).
- **Interval:** one `every` (steps) for position, velocity and box together; no separate velocity stride.
  Existing examples and validation configs write no velocities (`every` = 50–100 steps, 100–200 fs).
- **Integrator:** velocity Verlet, kick–drift–kick, so stored velocities are full-step values; they include
  thermostat action (`dynamics.rs`, `thermostat.rs`). The electrolyte protocol runs without constraints.
- **Analysis side:** `io.py::read_h5md` does not read velocities and `Trajectory` has no velocity field. Only
  checkpoints always store velocities. **A data path is missing at both ends.**
- **Size (mine):** 7 000 atoms × 3 × 4 B (float32) ≈ 84 kB per frame; 10 fs stride gives 10⁵ frames per ns
  ≈ 8 GB/ns. Storing atomic velocities for 20–170 ns runs is therefore not feasible, but is for the short
  comparison runs below.

## 3. Options for the input

| | Input | Cost | Independent of Einstein? |
|---|---|---|---|
| A | H5MD velocities, short run at fine stride (`every` 5–10, `velocities = true`) | storage, spec-neutral | yes (velocities are measured, not differenced) |
| B | finite-difference current J ≈ ΔR/Δt from positions | none | no: algebraically the Einstein form |
| C | engine writes the species currents J_i as an H5MD observable at a fine stride | a spec addition (engine, spec) | yes; fits long runs |

**Proposal (mine):** implement A in `ucmd-analysis` (read optional velocities, COM velocity per molecule
Σmv/M, species sums, barycentric correction) and run the comparison on a short dedicated run; list C as a
follow-up for long runs and do not start it without a spec decision. B is only a test of the code.
Barycentric frame: with thermostats the total momentum need not be exactly zero, so J_i is shifted by the
barycentre velocity as for positions (consistent with `molecules.barycentric`).

## 4. Cutoff of the integral

Facts from the code: `viscosity.green_kubo` evaluates the integral up to `max_lag_ps` (default 5 ps), returns
the running integral subsampled "so that this can be checked", and requires blocks ≥ 4× the lag count. The
Einstein form fits a window of 0.1–0.5 of the block's longest lag (`FitWindow`) and identifies the Fickian
regime with β(t) ≈ 1 (Lehnert SI §S1.3).

Options (mine):

1. **Same window as Einstein:** mean of the running integral I(t) over the Einstein lag window. By §1 this
   reproduces the Einstein slope up to discretisation; useful only as a unit test.
2. **Plateau window:** report I(t) ± block SEM and take the mean over a window where I(t) is flat within
   its SEM. The window is fixed before comparing with the Einstein value, to avoid tuning.
3. **Fixed t_c** from the decay of the normalised ACF, as the viscosity code does.

Known difficulty (stated in the literature as general knowledge, not checked here): the variance of
I(t) grows with t, while the ACF decays, so a plateau may be absent when distinct (L₊₋) terms are noisy.
For those, "no plateau resolved" is a legitimate result and is reported rather than forced.
Recommended: 2, with 1 as test.

## 5. Error estimate

- Consecutive blocks as in `uncertainty.blocks()` and `mean_sem()`; I(t) per block with SEM as a function of t.
  Replicas where available. The block length must exceed t_c by a margin (viscosity code: 4×).
- The SEM of the plateau mean is taken from the blocks, not from a single I(t); correlation of neighbouring
  lags within the window is ignored, so this underestimates (flagged, mine).
- Systematic part: sampling-interval bias of the discrete sum, estimated by re-evaluating at 2× and 4× stride
  on the same run (mine).

## 6. Tests

1. **Synthetic OU velocities** with known D (the issue's example): N independent particles with component
   variance σ² and correlation time τ have D = σ²τ and L = N·D/(k_B T V) (mine, from (1)); Einstein and GK both
   within their errors of this value.
2. **Correlated pair:** two species with a shared OU component, known L₊₋ ≠ 0 (analytic from the shared
   variance); both forms recover the sign and magnitude.
3. **Equivalence:** I(t) ≡ ½ d/dt MSD to numerical precision on the same synthetic velocities (option 1).
4. **Barycentre:** a constant drift of all particles does not change L (frame invariance).
5. **Real trajectory:** comparison table of L₊₊, L₋₋, L₊₋, κ, t₊ for a short run with velocities, run by the
   author's agent (acceptance item of the issue). Verdict = agreement within errors; a statement about the
   uncertainty of the distinct terms is not a validation.

## 8. Risks and assumptions

| # | Risk | Handling |
|---|---|---|
| 1 | GK and Einstein are identical for the same data (§1); agreement can be mistaken for validation | state it in the report, tests 3 vs 1–2 |
| 2 | Relation (1) is my derivation | tests 1–3 |
| 3 | Short run: distinct terms unresolved (pilot: none after 20 ns) | compare self terms and L₊₊, L₋₋ reliably; L₊₋ only as consistency |
| 4 | Velocities include thermostat action (CSVR / Nosé–Hoover) | check the ACF against an NVE segment |
| 5 | Coarse stride aliasing the velocity ACF | stride study (§5) |
| 6 | Storage cost for option A | short run only; option C for long runs |
| 7 | Plateau selection tuned after the fact | window fixed beforehand |
| 8 | Barycentre drift from the thermostat | barycentric shift as for positions |
