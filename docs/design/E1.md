# E1 design — minimal engine (NVE/NVT, PBC, Lennard-Jones)

- **Status:** approved at Gate 0 (2026-11-12). The §10 questions are settled as implemented (gate-0.md §7).
  Implemented on branch `e1` of ucmd-engine; the implementation awaits Gate E1.
- **Scope:** PLAN.md E1.1–E1.12. Spec: spec v0.1. Related ADRs: 0001–0007.

## 1. Crates and external dependencies

## 3. `ucmd-force`

- **Trait:** `ForceProvider` exactly as PLAN.md §2.4. In `evaluate(positions, cell, req, out)`,
  `out` is a caller-owned `ForceResult` that the provider overwrites. `energy: Option<f64>`
  (None when not requested).
- **`Observable`:** `{ name: String, unit: String, value: ObservableValue }`, where
  `ObservableValue` is `Scalar(f64)` or `Array(Vec<f64>)`.
- **`Guarded<P>`** wraps any provider. After every evaluation it checks:
  - `forces.len() == N`;
  - all values finite;
  - energy present when requested;
  - virial present when requested and the capability is set;
  - energy terms sum to the energy within 10⁻¹⁰ relative (debug builds and tests only).

  A violated check becomes `ForceError::Contract(String)`, a new category that never comes from
  a provider itself.
- **`Composite`:** children `Vec<(String, Box<dyn ForceProvider>, ForceResult)>`.
  - Energies, forces and virials add up; energy terms are prefixed with `child_name/`.
  - Capabilities: AND for `periodic`, `virial` and `deterministic`; OR for `energy_terms`.
- **`testkit`** (feature): the generic provider checks of spec/force-provider.md §6, each
  returning a report struct with the numbers, so tests can print them:
  - `fd_force_check(&mut dyn ForceProvider, &System, &State, &FdOptions) -> FdReport`, using
    central differences, the step-size scan, the best-h selection, and the relative error on
    components above the threshold;
  - `fd_virial_check`, using strain ±ε on positions and cell;
  - `energy_terms_check`, `momentum_check`, `determinism_check`;
  - deliberately broken providers (sign, factor 2, off-by-one) live in the testkit's own tests,
    as required by E1.2.

## 4. `ucmd-providers-classical` (E1)

- **`HarmonicTether`** (`kind = "harmonic-tether"`):
  - E = ½ k Σ \|r_i − r⁰_i\|² with `k_kjmol_nm2` and an anchor;
  - `anchor = "origin"` (default) or `"initial"`;
  - periodic: no (a tether in a periodic cell is ill-defined).
- **`HarmonicPairSpring`** (tests only; not in the registry): E = ½ k (\|r_ij\| − r₀)², with
  minimum image when periodic.
- **`LennardJones`** (`kind = "lennard-jones"`):
  - keys: `cutoff_nm`; `cutoff_mode` = `truncate` | `potential-shift` | `force-switch` (the last
    with `switch_nm`); `dispersion_correction` (bool); `neighbor_skin_nm` (default 0.1);
  - pair tables per atom-type pair, built from the combination rule;
  - exclusions are ignored in E1 (no bonds in the E1 fixtures). The provider **rejects**
    packages with bonds until E2.2, rather than silently computing wrong forces;
  - virial = Σ_{i<j} r_ij ⊗ F_ij;
  - dispersion correction for energy and virial (single and multiple types:
    ⟨ΣN_iN_j ε_ij σ_ij³ …⟩).
- **`NeighborList`:**
  - a cell list on fractional coordinates, then a half Verlet list with skin;
  - rebuilt when max\|r − r_build\| > skin/2. Positions are unwrapped, so no minimum image is
    needed for that test.
  - Used by LJ through a trait so that brute force (tests) and the list are interchangeable.

## 5. `ucmd-md`

- **Operators** are free functions on slices, so they compose without a framework:
  - `kick(v, f, inv_m, dt)` — B;
  - `drift(x, v, dt)` — A;
  - thermostats via trait `Thermostat { fn apply(&mut self, v: &mut [Vec3], m: &[f64], dof: f64, dt: f64, rng) -> f64 }`
    returning the kinetic energy added (bath energy −= that).
- **Integrator** `VelocityVerlet` with an optional thermostat.
  - Step: O(½) B(½) A(1) F B(½) O(½), with the O steps only when a thermostat is configured.
  - Forces are computed once per step; the force buffer carries over to the next step.
- **CSVR** (Bussi 2007): exact single-step update of the kinetic energy with the gamma/normal
  draws of the paper (rand_distr). The bath energy is accumulated, so
  `conserved_energy = K + E_pot − bath`.
- **Momentum** handling and **DOF** (single function `degrees_of_freedom`).
- **Observables:** K, T, kinetic tensor, P tensor = (K_tensor·2 + W)/V converted to bar, volume,
  `conserved_energy`.
- **RNG:**
  - one `ChaCha8Rng` per stream (velocity init = 1, thermostat = 2), seeded from
    `run.seed` with `set_stream`;
  - checkpoints store (seed, stream, word_pos);
  - velocity generation: Maxwell–Boltzmann per atom, then COM removal, then exact rescaling
    to the target temperature with N_dof (deterministic, documented).
- **Run loop:** `Simulation::run(steps, observers)`.
  - The loop keeps the **last good state** by double buffering. The drift writes into the
    spare position buffer, and buffers swap only after a successful force evaluation. On a
    provider error the current buffers are intact, at no copy cost.
  - Observers implement `Observer::observe(&Snapshot)` and declare their interval; the loop
    requests energies and virials only on steps where an observer needs them.

## 6. `ucmd-io`

- **`read_package(dir) -> Result<(System, State), SpecError>`:**
  - implements the checks and **error codes** of system-package.md §7, in the same order as
    the Python validator;
  - `SpecError { code: ErrorCode, message, location }`;
  - a contract test runs every fixture in `$UCMD_SPEC_DIR/fixtures` and compares the codes
    with `expected.json`;
  - minimal NPY 1.0/2.0 reader (about 60 lines, no dependency).
- **`load_run_config(path) -> Result<RunConfig, SpecError>`:**
  - serde structs with `deny_unknown_fields`, except provider tables, which are passed on as
    `toml::Table`;
  - codes E_TOML, E_VERSION, E_PATH, E_SCHEMA, E_INCOMPATIBLE;
  - `RunConfig::resolved_toml()` gives the fully resolved config for provenance.
- **Machine profile:** loaded per ADR 0002, defaults when absent.
- **Outputs:**
  - `H5mdWriter` (spec profile, ADR 0004);
  - `ThermoWriter` (TSV, header with units);
  - `XyzWriter` (extended XYZ, debug).

  All three implement `Observer`.
  - `Observer` and `Snapshot` (state, force result, kinetic quantities, conserved energy) are
    defined in `ucmd-force::observe`.
  - `ucmd-md` calls them and `ucmd-io` implements them, so `ucmd-io` never depends on `ucmd-md`
    (dependency rules, `scripts/check-architecture.sh`).
- **Checkpoints** (spec/checkpoint.md):
  - layout: magic `UCMDCHK\0`, format version u32, length-prefixed JSON metadata (versions,
    hashes, step, time, RNG states, thermostat state, output bookkeeping; f64 values written
    with shortest round-trip formatting, hence exact), then raw little-endian f64 arrays
    (positions, velocities, cell);
  - atomic write via `.tmp` + rename.

## 7. `ucmd-cli` (binary `ucmd`)

| Command | Behaviour |
|---|---|
| `ucmd check <package-or-run.toml>` | validates; prints `OK`/`INVALID` + code, like `ucmd-spec`; exit 0/1/2 |
| `ucmd run <run.toml> [--restart <checkpoint>] [--threads N]` | runs; emergency checkpoint and exit 1 on provider errors |
| `ucmd singlepoint <run.toml> [--forces out.npy]` | energy, terms, virial of the initial state as JSON |
| `ucmd rerun <run.toml> --trajectory <h5> --out <h5>` | providers evaluated on every frame; observables written |

- **Provider registry:** `match kind { "lennard-jones" => …, "harmonic-tether" => … }`, so adding
  a provider means one line plus a crate dependency, and only in `ucmd-cli`.
- **Provenance:** `build.rs` records `git rev-parse HEAD` ("unknown" outside git) and the
  dirty flag.
