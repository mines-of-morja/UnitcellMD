# E3.7 design — OpenMM as GPU backend (as built)

- **Status:** implemented 2026-11-17 on engine branch `e37-openmm`. The author approved the
  research plan, with GPU-first throughput (decision D3). The decisions below are open for review
  at the gate.
- **Evidence:** `ucmd-engine/validation/e37-openmm/REPORT.md`.

## Architecture

- **Machine profile `[backend]`** (`kind = "openmm"`, `platform`, `precision`, `device`) plus
  `[executables] ucmd-openmm`. Packages and `run.toml` are unchanged (ADR 0010 §1). The GUI and
  the study driver keep calling `ucmd run`.
- **`ucmd run`** computes the reference single point and execs the bridge:
  - CPU backend, start positions displaced by a seeded 0.01 nm (stream 4);
  - files in `out/backend-reference/`.
- **`ucmd-engine/bridge`** (Python, `ucmd-bridge`):
  - reads the package;
  - builds the OpenMM System, with the engine's PME α and grid set explicitly;
  - checks conformance (1e-6 / 1e-5) and refuses to run otherwise;
  - runs the engine's integrators as CustomIntegrators: velocity Verlet, the Nosé–Hoover chain
    (same Suzuki–Yoshida propagation and masses), Langevin BAOAB, all with full-step velocities;
  - writes thermo, H5MD or XYZ in the spec formats;
  - restarts from its own checkpoint; stops gracefully on SIGINT/SIGTERM.
- **The GPU stack lives in a container** (`bridge/docker`: a ROCm base plus conda-forge OpenMM
  with OpenCL), run by a wrapper script. The host needs no ROCm or OpenCL.

## Deviations from the engine (each recorded in the H5MD provenance)

- **Barostat:** MonteCarloBarostat instead of C-rescale (same ensemble; validated for argon in
  E2.7).
- **Pressure:** the molecular pressure from MonteCarloBarostat.computeCurrentPressure, every
  500 steps (nan in the other thermo rows). OpenMM has no virial.
- **Not available:** CSVR, constraints, anisotropic coupling (all refused).

## Questions for the author

1. **Precision:** double passes ADR 0010 at 34 ns/day. Mixed runs at 77 ns/day, but forces
   deviate by 5.5e-5 relative (tolerance 1e-5). Amend ADR 0010 for mixed precision, with a
   statistical-level validation instead, or stay with double?
2. **RX 580:** ROCm 7 does not support it. It needs Mesa's OpenCL (rusticl) on the host, a
   system package (sudo). Install it?
3. **Spec v0.1.1:** document the profile's `[backend]` section (spec/run-config.md §4), together
   with the other pending items (stop exit codes, restart records, XYZ trajectory).
