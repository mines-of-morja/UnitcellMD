## 1. Package layout and dependencies

```
ucmd-builder/src/ucmd_builder/
  recipe.py        Recipe model of build.toml: parse, validate, write back (stable round trip)
  molecule.py      MoleculeGraph; readers for SMILES, MOL/SDF, PDB, XYZ (RDKit); angles and
                   dihedrals from the bond graph
  forcefield/
    api.py         ForceFieldSource protocol, Conventions, Parameterized, Citation, SourceError
    registry.py    discovery through the entry-point group ucmd_builder.forcefield_sources
    library.py     source "library": curated data sets in ucmd_builder/forcefields/
    gromacs.py     source "gromacs-top": importer for .top/.itp files
    transforms.py  ion charge scaling ζ (more transforms later)
    units.py       conversions at the import boundary (kcal/mol, Å, K(x−x₀)² → spec)
    testkit.py     the checks that every source must pass (§4.6)
  forcefields/     data: <set>/set.toml and <molecule>.toml
  composition.py   composition calculator (B1.4)
  packing/         packmol.py (driver), insertion.py (built-in packer), checks.py (PBC distances)
  crystal.py       B1.6
  initial.py       B1.7: Maxwell–Boltzmann velocities, Wigner sampling
  export/          package.py (system package), lammps.py, xyz.py (B1.9)
  build.py         build(recipe, progress=None, cancel=None) -> BuiltSystem; the one entry
                   point for the CLI and, later, the GUI
  constants.py     CODATA 2018 constants (ADR 0001) and standard atomic weights (CIAAW)
  cli.py           ucmd-build
```

| Dependency | Licence, size | Why |
|---|---|---|
| numpy | BSD | arrays, NPY files, seeded RNG (PCG64) |
| rdkit 2026.9 | BSD, 29.5 MB wheel | molecule input, SMILES, bond perception, graph matching (already planned in PLAN.md §2.1) |
| ucmd-spec | this umbrella repo, git dependency pinned to `spec-v0.1.0` (`subdirectory=spec/validator`) | every package the builder writes is validated by the reference validator |
| extra `packmol` | official PyPI wheel 21.2.3 by the Packmol authors, MIT, 1.2 MB | packing without sudo (§7). Debian's `packmol` 21.0.2 would need sudo |
| extra `crystal` | ase (LGPL-2.1), spglib (BSD) | CIF import, symmetry (B1.6) |
| extra `gui` | PySide6, pyvistaqt (ADR 0006) | B2 |

Recipes are read with `tomllib` (standard library) and written with `tomli-w` (tiny) for the
GUI.

## 2. Data model

| Type | Content |
|---|---|
| `MoleculeGraph` | name; elements in canonical order; bonds `(i, j, order)`; per-atom formal charges; total formal charge z; optional coordinates in nm; canonical SMILES (RDKit) as identity |
| `Parameterized` | the output of a source, in the graph's atom order. Per atom: type, `charge_e`, optional `mass_amu`. LJ per type: σ in nm, ε in kJ/mol. Bonds, angles, dihedrals and impropers in the spec forms (system-package.md §5.3) with params in spec units. Also `Conventions`, citations and `source_id` (name, version, data set, options hash) |
| `Conventions` | `combination_rule`, `scale_14_lj`, `scale_14_coulomb`, `family` (informative, e.g. "OPLS-AA") |
| `Component` | name; molecule (library name, SMILES or file); count; optional force-field override; transforms |
| `Recipe` | seed; components; box (density or length) or a composition block; packing; optional velocities; output options |
| `BuiltSystem` | molecule types (graph + parameters after transforms), counts, cell, positions (nm, unwrapped), optional velocities, provenance |

All types are frozen dataclasses with type hints. `build()` is a pure function of the recipe,
its seed, the data files and the external program versions.

## 3. Recipe `build.toml`

```toml
format = "ucmd-build"
version = "0.1"
seed = 20261112

[forcefield]                         # default for every component
source = "library"
set = "opls-aa-carbonates"           # proposal §5; name to be fixed when the data exist

[composition]                        # optional: fills the counts below (B1.4)
salt = ["Li", "PF6"]
molarity_mol_L = 1.0
solvent = { EC = 0.3, EMC = 0.7 }    # mass fractions
solvent_molecules = 500
density_g_cm3 = { value = 1.2, source = "…" }   # cited; also gives the box length

[[component]]
name = "EC"
molecule = { library = "EC" }        # or { smiles = "O=C1OCCO1" } or { file = "ec.sdf" }

[[component]]
name = "EMC"
molecule = { smiles = "CCOC(=O)OC" }
forcefield = { source = "gromacs-top", file = "ff/emc.itp", conventions = "opls" }

[[component]]
name = "Li"
molecule = { smiles = "[Li+]" }
charge_scale = 0.75                  # ζ, Lehnert 2025 SI Table S3

[[component]]
name = "PF6"
molecule = { smiles = "F[P-](F)(F)(F)(F)F" }
charge_scale = 0.75

[packing]
method = "packmol"                   # or "insertion"
tolerance_nm = 0.20
```

- Counts may be given directly with `count = …` instead of a `[composition]` block.
- Unknown keys are errors, as in `run.toml`.

## 4. Force-field sources (ADR 0008)

### 4.1 Interface

```python
class ForceFieldSource(Protocol):
    name: ClassVar[str]            # "library", "gromacs-top", …
    version: ClassVar[str]
    def parameterize(self, molecule: MoleculeGraph,
                     options: Mapping[str, object]) -> Parameterized: ...
```

- **Deterministic and offline:** no network and no randomness. A source that runs an external
  program records the program's version.
- **Order:** results come in the molecule's canonical atom order. Matching and reordering
  happen inside the source.
- **Errors** raise `SourceError` with an actionable message, e.g.:
  - "no template in set X matches EMC (C4H8O3)";
  - "file.itp uses [ pairtypes ], which spec v0.1 cannot express".

### 4.2 Registry

- The registry discovers sources through `importlib.metadata.entry_points(group=
  "ucmd_builder.forcefield_sources")`.
- The built-in sources register in the builder's own `pyproject.toml` the same way, so the
  plug-in path is always exercised.
- A third-party package adds, for example, `openff = "ucmd_ff_openff:OpenFFSource"`. The
  builder needs no change.
- Two sources with the same name are an error that names both distributions.
- `ucmd-build sources` lists every source with its name, version, distribution and conventions.

### 4.3 Assembly rules

- **Conventions:** a package has one `Conventions`. If the components' sources disagree,
  `ConventionMismatch` lists them. Per-pair overrides would need a spec extension (ADR 0008 §3).
- **LJ types** share one namespace per package. The same name with the same values is fine; the
  same name with different values is an error.
- **Masses** come from the source when it provides them, as GROMACS files and OPLS tables do.
  Otherwise they are the CIAAW standard atomic weights from `constants.py`. The choice is
  recorded in provenance. The engine never guesses masses (invariant 5).
- **Transforms** run after parameterization and are recorded in `provenance.transforms`.
  `charge_scale = ζ` multiplies every partial charge of the component's molecule type, so the
  net charge becomes ζ·z (`formal_charge_e` stays z). Exclusions are unaffected.
- **Unparameterized packages** (`source = "none"`): elements, masses and topology only. This is
  for ML or QM force providers (E3).

### 4.4 Built-in source `library`

- **Data sets:** each set is a directory `forcefields/<set>/` with a `set.toml` holding the name,
  family, conventions, citations, data licence and notes. Each molecule template is one
  `<molecule>.toml` file with:
  - atoms: element, type, charge, optional mass;
  - bonded terms;
  - LJ types;
  - reference coordinates;
  - SMILES.
- **Values are stored as printed in the source**, with declared units and conventions (e.g.
  `energy = "kcal/mol"`, `length = "angstrom"`, `harmonic = "K(x-x0)^2"`). Every entry can then
  be checked line by line against the paper, with comments such as `# Table 2`. They are
  converted to spec units exactly once, at load, by `forcefield/units.py`.
- **Matching** is a graph isomorphism between the input molecule and the template:
  - element-labelled connectivity, via RDKit substructure matching with element-only atom
    queries and any-bond queries, and equal atom counts;
  - formal charges and bond orders are then compared where the input has them;
  - the match gives the atom mapping.

  Atoms that are equivalent by symmetry must have equal parameters in the template. The loader
  checks this over the template's automorphisms, so any match is correct.
- **Bonded terms:** templates list angles, dihedrals and impropers explicitly, as the sources
  do. The test kit cross-checks them against the bond graph.

### 4.5 Built-in source `gromacs-top`

GROMACS topologies are the most widely shared force-field exchange format, so this importer
connects most existing generators at once:
- LigParGen;
- ATB;
- ACPYPE (GAFF/GAFF2 via AmberTools);
- OpenFF Interchange;
- CHARMM-GUI;
- many published force-field repositories.

GROMACS units are spec units (nm, kJ/mol, degrees, ½k harmonic forms), so conversion is almost
the identity.

**Supported:**

| Directive | What is read |
|---|---|
| `[ defaults ]` | nbfunc 1; comb-rule 2 → `lorentz-berthelot`, 3 → `geometric`; gen-pairs yes; fudgeLJ and fudgeQQ → the 1-4 scales |
| `[ atomtypes ]`, `[ moleculetype ]` (nrexcl 3), `[ atoms ]` | types, LJ, charges, masses |
| `[ bonds ]` | funct 1 |
| `[ angles ]` | funct 1 |
| `[ dihedrals ]` | 1 and 9 (periodic), 3 (Ryckaert–Bellemans), 5 (Fourier), 2 (harmonic improper), 4 (periodic improper) |
| `[ pairs ]` | funct 1 without parameters. The list must equal the 1-4 pairs of the bond graph |
| `[ constraints ]`, `[ settles ]` | model constraints (rigid water) → spec `constraints` |
| preprocessor | `#include` of local files; `#ifdef POSRES` blocks are skipped |

**Refused with a clear error**, because spec v0.1 cannot express it:
- `[ pairtypes ]` or pairs with explicit parameters;
- `[ exclusions ]` or nrexcl ≠ 3;
- comb-rule 1;
- Urey–Bradley angles, CMAP, virtual sites;
- any other directive or preprocessor command.

**Missing `[ defaults ]`:** some files have no `[ defaults ]` section (a LigParGen `.itp`, for
example). Then the conventions come from the recipe: the preset `conventions = "opls"` means
geometric, 0.5, 0.5.

**Atom order:** the GROMACS `[ atoms ]` order is mapped to the recipe molecule by the same graph
matching as in `library`.

### 4.6 Source test kit

`forcefield.testkit.check_source(source, molecules, options)` is the builder counterpart of the
engine's provider test kit. Every source, built-in or plug-in, passes it:

1. the atom count and canonical order are preserved, and every atom has a type and a charge;
2. every bond has parameters, and the angle and proper-dihedral sets agree with the bond graph.
   Dihedrals that are absent (zero barrier) are reported, not failed;
3. the net charge equals the formal charge to 10⁻⁶ e, before transforms;
4. the conventions are complete and allowed by the spec;
5. sanity ranges catch unit mix-ups:
   - σ in [0.05, 0.6] nm, or σ = ε = 0;
   - ε in [0, 5] kJ/mol;
   - bond r₀ in [0.08, 0.3] nm;
   - bond k in [10⁴, 10⁶] kJ mol⁻¹ nm⁻²;
   - angle θ₀ in (60°, 180°];
   - angle k in [10, 2000] kJ mol⁻¹ rad⁻²;
6. there is at least one citation;
7. two calls give identical results;
8. a package built from the result passes `ucmd-spec validate`.

### 4.7 Planned plug-ins (not part of B1)

- **`openff` (OpenFF Sage):** the toolkit is on PyPI, but charges need AmberTools or NAGL from
  conda-forge. It becomes a separate package (`ucmd-ff-openff`) with its own environment.
  Without the plug-in, Interchange can write GROMACS files for `gromacs-top`.
- **GAFF2:** via ACPYPE/AmberTools, then GROMACS files, then `gromacs-top`.
- **Graph-network generators** (ByteFF, espaloma, Grappa): as plug-ins if their licences fit
  (ADR 0008 landscape).
- **Our own fitted force field:** ADR 0008 §6.

## 5. Working horse for carbonate electrolytes (proposal; becomes ADR 0009 on approval)

**Proposal:** OPLS-AA, the force-field family of Lehnert 2025, with openly published parameters
only.

| Species | Parameters | Source | Openness |
|---|---|---|---|
| Li⁺ | σ, ε | Jensen & Jorgensen, J. Chem. Theory Comput. 2, 1499 (2006), as in Lehnert | published |
| PF₆⁻ | bonds, angles, σ, ε, charges | CL&P, Canongia Lopes & Pádua (2004), as cited in the Lehnert SI | published; CL&P database MIT |
| EC, EMC (later DMC, PC, MP) | OPLS-AA atom types and bonded terms, 1.14·CM1A-LBCC charges | LigParGen: Dodda et al. 2017 (Nucleic Acids Res.; J. Phys. Chem. B), Jorgensen & Tirado-Rives 2005 | free server; the generator (BOSS) is not open source; the output has no stated terms |
| ζ | 0.75 for Li⁺ and PF₆⁻ in EC:EMC | Lehnert 2025 SI, Table S3 | published |

**Why:**
- **Attributable deviations.** The functional form, the mixing rule, the 1-4 scaling and the ion
  parameters are the benchmark's. Only the solvent parameters differ (Maestro OPLS_2005 →
  OPLS-AA/1.14·CM1A-LBCC), so any deviation from Lehnert can be attributed to them.
- **No closed code in our pipeline.** LigParGen is the OPLS developers' own generator for small
  molecules. Its GROMACS output enters through `gromacs-top`.
- **A fully open alternative exists:** OpenFF Sage (§4.7). It is a different family
  (Lorentz–Berthelot mixing) and needs conda for its charges. It is the first candidate for a
  sensitivity check, and the fallback.

**Evidence before it becomes the default.** The thresholds are proposals; the author confirms
them.
- Pure EC at 313 K and pure EMC at 298 K: density within 2 % of experiment.
- 1 M LiPF₆ in EC:EMC 3:7 at 293 K: density within 2 % of Landesfeind 2019 or Logan 2018.
- Li⁺ first shell (Li–O carbonyl, Li–F) compared with Lehnert and the literature. This is
  reported, without a threshold.
- κ and t⁺ follow in A2.

If the set fails, the next candidates are OpenFF Sage and our own refit (ADR 0008 §6).

## 6. Composition calculator (B1.4)

- **Inputs:**
  - salt (cation, anion);
  - concentration (mol/L or mol/kg);
  - solvent ratio (mass or volume fractions);
  - size target: ion pairs, solvent molecules, atoms or box length;
  - density, with its citation.
- **Outputs:** integer counts, the box length, and the achieved concentration and solvent ratio
  after rounding.
- **Masses** are those of the parameterized molecules, i.e. the masses written into the package.
- ✓ 1 M LiPF₆ in EC:EMC 3:7 w:w with 500 solvent molecules gives exactly 168 EC + 332 EMC
  (Lehnert Table S1).
  - The ion pairs follow from the experimental density and are reported.
  - Lehnert's 47 is expected within ±2: they tuned the ion count by simulation (SI notes).
- ✓ The molarity ↔ molality round trip holds.
- ✓ Volume fractions work with pure-solvent densities (Lehnert Table S2: EC 1.321, EMC 1.006
  g/ml).

## 7. Packing (B1.5)

**Packmol driver:**
- **Executable:** taken from the machine profile `[executables] packmol` (spec/run-config.md §4).
  - Proposed fallback: the Packmol of the builder's own environment, from the extra
    `ucmd-builder[packmol]`.
  - `PATH` is never searched. The version is probed and recorded.
- **Input:**
  - one structure per component (template coordinates, in Å at this boundary);
  - `inside cube`;
  - Packmol's periodic `pbc` box;
  - tolerance (default 0.20 nm);
  - `seed` derived from the recipe seed;
  - a timeout.
- **Checks:**
  - exit status and Packmol's success message;
  - molecules are made whole relative to their first atom (unwrapped, D11);
  - canonical order: Packmol writes components in input order and atoms in template order.
- **GUI hooks:** Packmol's progress lines go to the `progress` callback; `cancel` kills the
  process.

**Built-in insertion packer** (tests, small systems, no Packmol): random rigid insertion with
random orientation, an overlap test under PBC with a cell list, and retries. It is
deterministic per seed (numpy PCG64).

**Check after either method:** the minimum intermolecular distance under PBC is at least the
tolerance. Otherwise the error names the closest pair.

**Criteria:**
- ✓ The result is deterministic per seed (for a given Packmol version).
- ✓ No pair is closer than the tolerance across periodic boundaries.
- ✓ Molecules are whole.

## 8. Crystals (B1.6) and initial conditions (B1.7)

As in PLAN.md:
- **Crystals:** CIF via ASE, symmetry via spglib, supercells from an integer matrix, reduction to
  the spec cell form, and site-based types and charges from a library set.
- **Velocities:** Maxwell–Boltzmann, seeded with the COM removed. Only written when the recipe
  asks for them, since the engine can also generate velocities.
- **Wigner sampling:** from a Gaussian fchk Hessian, following the equations of
  `WignerBase.py` (reimplemented, not copied).

## 9. Export, determinism, provenance (B1.1, B1.8)

- **`export_package(built, directory)`** writes `system.json` (stable key order and number
  formatting), `positions.npy` and, if requested, `velocities.npy`. It then runs the `ucmd-spec`
  validator, and a failure is an error.
- **Provenance** contains:
  - `created_by`: builder version and git hash;
  - `created_utc`;
  - the recipe, both verbatim and resolved;
  - the seed;
  - `sources`: the citations of every source, of the densities and of the Packmol version;
  - `transforms`.
- ✓ The same recipe and seed give a byte-identical package, except for `created_utc`.

## 10. Exporters (B1.9)

- **LAMMPS data** (`full` style) and **extended XYZ** (Å).
- **OpenMM:** stays the single converter in `tools/oracle/` (umbrella repo). It is extended to
  bonded terms, exclusions and 1-4 pairs, and PME, which M2a and E2.9 need.

## 11. CLI

```
ucmd-build build build.toml -o pkg/      recipe → validated package
ucmd-build compose …                     composition calculator: counts, box, achieved values
ucmd-build sources                       installed force-field sources
ucmd-build library [--set NAME]          templates in the library
ucmd-build check pkg/                    the ucmd-spec validator, for convenience
```

## 13. Order of work and a proposed split

To reach M2a, and with it the frontend, sooner, B1 is split in two.

- **B1a, needed for M2a:**
  1. B1.1 → B1.2 → B1.3. B1.3 covers the sources and the test kit; the library first gets argon
     and SPC/Fw, then the electrolyte set after the author's decision on §5.
  2. B1.4 → B1.5 → B1.8.
  3. The extension of the oracle converter.
- **B1b, later or in parallel with E2:** B1.6 crystals, B1.7 Wigner sampling, B1.9 LAMMPS/XYZ
  exporters.

Work happens on branch `b1` of ucmd-builder, with one commit per task.
