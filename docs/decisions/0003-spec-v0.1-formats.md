# 0003 — Spec v0.1 formats

- **Status:** accepted provisionally on 2026-11-12 by the agent, while the author was away
  ("make the best decisions for the project"). To be reviewed at Gate 0.
- **Context:**
  - PLAN.md D4–D6 and D11 set the direction: JSON + NPY packages, TOML configs, H5MD
    trajectories, molecule type × count, separate system and run, unwrapped positions.
  - P0.3 had to turn this into exact rules that two languages can implement identically.
- **Decision:** the choices below. Each is normative in the spec documents. The ones most worth
  a second look are marked ★.

  1. ★ **One `system.json` per package**, plus `positions.npy` and an optional
     `velocities.npy`. PLAN.md had a manifest plus a topology file per molecule type. A single
     file is simpler for every reader. Reuse of molecule definitions happens in the builder's
     template library, not in packages.
  2. ★ **Everything is a molecule type × count.** There is no separate "explicit atoms"
     component kind. Crystals use single-atom types, or one large type with count 1 when
     intramolecular bonds are needed.
  3. ★ **Mass unit = g/mol (labelled `amu`)**, so 1 (g/mol)·nm²·ps⁻² = 1 kJ/mol exactly. The
     dalton per particle differs by 3.5×10⁻¹⁰ since the 2019 SI redefinition.
  4. **Unit suffixes on every key with a unit** (`r0_nm`, `k_kjmol_nm2`, `theta0_deg`), in
     packages and configs alike. Angles are in degrees in files and radians internally.
  5. ★ **Bonded parameters are explicit per interaction** (atoms + form + params). The engine
     never matches atom types to parameters; that is the builder's job. Atom types exist only
     for Lennard-Jones parameters.
  6. **Harmonic forms are written with ½** (½k(r − r₀)²). Sources using K(r − r₀)², such as
     LAMMPS and many OPLS tables, are converted with k = 2K by the producer.
  7. **Exclusions by shortest bond-path distance:** d ≤ 2 excluded, d = 3 scaled (1-4). This
     matches LAMMPS `special_bonds` (used by Lehnert 2025) and OpenMM
     `createExceptionsFromBonds`.
  8. **Parameterized and unparameterized packages.** The presence of `forcefield` decides, and
     completeness is checked (`E_PARAMETERS`). QM/ML runs use unparameterized packages.
  9. **`formal_charge_e` per molecule type**, separate from the possibly ζ-scaled partial
     charges. κ and t⁺ need the formal charge numbers; QM providers need the total charge.
  10. **Unwrapped positions, whole molecules, no image flags,** everywhere: packages,
      trajectories, provider input.
  11. **Cell rows = lattice vectors, in reduced lower-triangular form** (GROMACS-style). The
      builder reduces cells.
  12. **Strict schemas:** unknown keys are errors, which catches typos like `r0` instead of
      `r0_nm`. While the major version is 0, a minor version may break compatibility; readers
      accept exactly their own minor version.
  13. **`run.toml`:** relative paths only (`E_PATH`). One or more `[[providers]]` tables, whose
      forces are summed; providers validate their own keys. Machine-specific settings live in
      a separate machine profile (ADR 0002).
  14. **Trajectory:** H5MD 1.1 with an embedded copy of `system.json` and of the resolved run
      configuration. The box is always stored as time-dependent. Species = atomic number;
      molecule index stored per atom.
  15. **Stable error codes** (`E_*`, `W_*`), shared by all readers. Contract tests compare the
      codes, not the messages.

- **Consequences:**
  - The validator (P0.4) and the engine reader (E1.4) implement exactly these rules and are
    tested against the same fixtures.
  - Changing any item after Gate 0 requires an ADR, the CHANGELOG, and updates of the
    fixtures and all readers.
